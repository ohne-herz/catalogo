Mantenedor del sitio

Esta versión corre 100% en GitHub Pages (sin servidor propio), por eso no existe un panel con usuario/clave real: cualquier "login" hecho solo con JavaScript en un sitio estático se puede saltar viendo el código fuente, así que no vamos a simular una seguridad que no existe.

El control real de acceso lo da GitHub: solo quien tiene permiso de escritura en el repo puede cambiar esta configuración. Esa es la seguridad de esta versión.

1. Cambiar el email de destino de los leads

  1. Ve al repo en GitHub → docs/assets/js/config.js
  2. Click en el lápiz ✏️ (Edit this file)
  3. Cambia el valor de targetEmail
  4. Commit directo a main (o crea un Pull Request si tu equipo lo requiere)
  5. GitHub Pages redespliega solo, en 1-2 minutos

2. Ver los leads recibidos

Como no hay base de datos propia, los leads quedan registrados en el dashboard de EmailJS (historial de emails enviados) y, principalmente, en la bandeja de entrada del targetEmail configurado.

3. Configurar EmailJS (una sola vez)

  1. Crea una cuenta gratis en emailjs.com
  2. Conecta tu proveedor de email (Gmail, Outlook, SMTP propio, etc.) como "Service"
  3. Crea un "Email Template" con variables: from_name, from_email, phone, device, to_email
  4. Copia Public Key, Service ID y Template ID a docs/assets/js/config.js
